# Terminal++ — 통합 AI 터미널 · Rust

Claude Design 프로젝트 `AI Terminal.dc.html` 를 Tauri 2.0 데스크탑 앱으로 구현한 것.
Windows Terminal 의 터미널 코어(ConPTY + VT 파서 + 셀 버퍼)를 Rust 크레이트로 다시 세우고,
분할 · 줄 병합 두 조작만으로 창을 배치하는 레이아웃을 얹었다.

## 빠른 시작

```bash
pnpm install
pnpm tauri dev          # 개발 실행
pnpm tauri build        # 릴리스 번들 (msi · nsis)
```

필요한 것: Node 20+ · pnpm · Rust 1.82+ (MSVC) · WebView2(윈도우 11 기본 포함).

앱 UI 글꼴은 구글 산세리프 두 벌을 겹쳐 쓴다 — 라틴/숫자는 **Roboto**, 한글은 **Noto Sans KR**.
터미널 본문은 윈도우 터미널의 기본 얼굴인 **Cascadia Mono**(400·700·이탤릭, 라틴 부분집합만
112 KB)를 첫 글꼴로 쓰고, 없으면 **Noto Sans Mono**, 한글은 **Noto Sans KR** 이 맡는다 —
Cascadia 와 Noto Sans Mono 에는 한글 글리프가 하나도 없다. 모두 로컬 번들이라 오프라인에서도,
Cascadia 가 깔려 있지 않은 윈도우에서도 같은 모양이 나온다.

한글 입력이 들어가는 칸은 전부 `TextField` 를 쓴다. 값을 Rust 로 보내고 돌아온 스냅샷을
그대로 되먹이면 IME 조합 중에 입력창이 덮어써져 커서가 튄다. 그래서 화면 값은 로컬 상태가
쥐고, 조합이 끝난 뒤에만 바깥으로 내보낸다.

**레이아웃과 터미널 버퍼의 단일 진실 공급원은 Rust다.** 프론트엔드는 분할·병합·교환을 스스로
계산하지 않고 명령을 부른 뒤 돌아온 스냅샷을 렌더한다. 병합 드래그 중의 미리보기조차
`layout_merge_check` 를 호출해 같은 판정을 받아 쓰므로 규칙이 두 벌 존재하지 않는다.

## 세션

세션은 창 배치 한 벌과 그 안에서 도는 셸들의 묶음이다. 왼쪽 목록에서 고르고, `＋` 로 만든다.

**`＋` 는 이름부터 묻는다.** 이름 칸에는 다음 기본 이름(`새 세션 3`)이 채워진 채로, 통째로
골라진 상태로 뜬다 — 그대로 엔터를 쳐도 되고 곧바로 다른 이름을 쳐도 덮어써진다. 세션을
만드는 것은 **엔터 또는 `생성`** 이고, `닫기`(· `✕` · `Esc` · 바깥 누르기)는 취소라 아무것도
만들어지지 않는다. 한글 조합 중의 엔터는 글자 확정이므로 만들기로 삼지 않는다.

**새 세션은 터미널 하나가 세션을 가득 채운 채로 열린다.** 예전에는 빈 블럭 하나로 태어나
"터미널 열기" 를 누르는 것 말고는 할 일이 없었다. 그 한 걸음은 Rust 가 대신 밟는다
(`layout::start_full_terminal` — 세션 만들기 한 번에 배치까지 끝난다). 처음 켤 때 만들어지는
세션도 같다. 곧바로 띄운 터미널을 덮어 버리지 않도록 설정 모달은 열지 않는다 — `Ctrl+,` 로 연다.

**사이드바가 접혀 있어도 세션을 만들 수 있다.** 40px 레일 맨 위의 `＋`, 또는 어디서나
`Ctrl+Shift+T`(윈도우 터미널의 "새 탭" 과 같은 자리). 명령 팔레트에도 있다. 모두 같은
이름 묻는 창으로 들어간다.

### 세션 설정 · `Ctrl+,`

이름 · 작업 디렉터리 · 셸 · 시작 명령(또는 SSH 호스트) · 환경변수를 고치고, 그 세션이 종료 후
무엇을 복원하는지 요약해 보여 준다.

**고치는 동안에는 아무것도 기록되지 않는다.** 화면이 초안을 쥐고 있다가 `저장` 을 누를 때
한 번에 세션으로 넘어간다 — 입력칸에서 엔터를 쳐도 같은 저장이다. `닫기`(· `✕` · `Esc` ·
바깥 누르기)는 취소라 초안을 버리고 세션은 그대로 둔다. 예전에는 칸을 고치는 즉시 기록돼
잘못 고친 것을 되돌릴 길이 없었다. 저장한 설정은 **다음에 여는 터미널부터** 적용된다 —
돌고 있는 셸은 그대로 산다.

## 레이아웃 조작

| 조작 | 방법 | 결과 |
| --- | --- | --- |
| 분할 | 창 클릭 → `⬍ 위·아래` / `⬌ 좌·우` (또는 우클릭 · 팔레트) | 창 하나 → 두 칸, 새 칸은 빈 블럭 |
| 줄 병합 | `⧉ 줄 병합` 켠 뒤 첫 창을 누른 채 같은 줄로 드래그 | 지나간 창들이 하나로 |
| 위치 교환 | `⇄ 위치 교환` 켠 뒤 두 창 클릭 | 좌표·크기 맞바꿈 |
| 크기 조절 | 창과 창 사이 경계를 끌기 | 한 창이 커진 만큼 이웃이 작아짐 |
| 크기 균등 | `⊟ 크기 균등` (팔레트에도 있음) | 모든 창을 같은 크기로 |
| 전체화면 | 제목줄의 `⤢` · 더블클릭 · 세션 헤더의 `⤢ 전체화면` · `Ctrl+Shift+F` | 그 창 하나가 세션 영역을 가득 채움 |

편집 모드는 `Ctrl+E`(터미널 안에서는 `Ctrl+Shift+E`).

### 나눈 자리의 터미널은 나눠 준 터미널의 폴더에서 시작한다

터미널을 우클릭해 나눴다면 대개 "이 폴더에서 하나 더" 라는 뜻이다. 그래서 터미널을 나눠 생긴
빈 블럭에 터미널을 열면 **나눠 준 터미널이 그때 서 있는 폴더**에서 뜬다. 빈 블럭이 무엇이 일어날지
미리 적어 주고(`터미널은 나눠 준 터미널의 폴더에서 시작합니다 · …`), 열고 나면 어디서 떴는지
토스트로 확인해 준다.

어느 폴더인지는 **탐색기로 열기와 같은 판정**이다(`reveal::resolve_folder`).

| 순서 | 폴더 |
| --- | --- |
| 1 | 나눠 준 터미널의 셸이 **지금** 알려 주고 있는 폴더(`live_cwd`) — 나눈 뒤 `cd` 했으면 바뀐 폴더 |
| 2 | 그 창에 마지막으로 적힌 폴더 — 셸 통합 마커가 없거나 셸이 끝났을 때 |
| 3 | 나눌 때 재 둔 폴더 — 나눠 준 터미널이 그새 닫혔을 때 |
| 4 | 세션 설정의 폴더 |

기억은 화면이 아니라 **스냅샷**에 있다 — 새 빈 블럭의 `splitFrom`(나눠 준 창 id + 나눌 때의 폴더).
예전에는 화면 상태라 분할 직후 경계를 끌어 크기만 바꿔도, 다른 창을 한 번 더 나눠도 잊었다. 지금은
교환·크기 조절·세션 전환·앱 재시작을 지나도 남고, 그 블럭에 무엇인가 열리면(터미널·파일·새 파일)
지워진다.

폴더는 탐색기와 같은 검사(`validate`)를 지난다 — 네트워크 경로(UNC)는 존재 확인만으로도 그 호스트에
붙으러 가 인증 정보를 흘리므로 물려주지 않고, 상대 경로·사라진 폴더도 다음 후보로 물러난다. SSH
세션에는 물려줄 폴더가 없고(원격 셸이라 아는 것이 없다), WSL 의 `/home/...` 경로는 윈도우에서 그대로
띄울 수 없어 세션 폴더로 돌아간다.

### 전체화면 · 창 모드

창이 하나뿐인 세션에서는 세션 테두리 안쪽에 창 테두리가 한 겹 더 그려져 테두리가 두 겹으로
보인다. 전체화면은 고른 창 하나만 남기고 판 여백·창 테두리·모서리를 걷어내 **세션 영역을
그대로 채운다** — 세션 이름·레이아웃 편집 버튼이 있는 위쪽 세션 헤더까지 그 창 하나가
덮어써서, 창이 세션 전체를 감싸는 모양이 된다. 창 자신의 제목줄은 남아 있어서 확대 배율·닫기·
`⤡` 로 창 모드로 돌아갈 수 있다.

- 켜기 — 제목줄의 `⤢`, 제목줄 더블클릭, 세션 헤더의 `⤢ 전체화면`, 우클릭 메뉴, 명령 팔레트,
  `Ctrl+Shift+F`.
- 끄기 — 세션 헤더는 전체화면 중엔 가려 있으므로, 창 제목줄의 `⤡`·더블클릭·우클릭 메뉴·
  명령 팔레트·`Ctrl+Shift+F` 로 돌아간다. 터미널을 가득 채운 상태에서도 `Ctrl+Shift+F` 는
  앱이 가져가므로 되돌릴 길이 항상 남는다(`Esc` 는 쓰지 않는다 — 셸과 `vim` 의 키다).
- **격자는 그대로 남는다.** 전체화면은 배치가 아니라 보는 방식이라, 창 모드로 돌아오면 나눠
  두었던 배치와 크기가 그대로 살아난다.
- 창이 숨는 상황은 만들지 않는다 — 분할·파일 열기·터미널 열기처럼 **새 내용이 생기면**
  자동으로 창 모드로 돌아가고, 레이아웃 편집(`Ctrl+E`)을 켤 때도 격자가 보이도록 풀린다.
  전체화면이던 창을 닫거나 병합으로 사라지면 역시 창 모드로 돌아간다.
- 상태는 세션마다 따로 기억되고 스냅샷에 남아 **다음 실행에서도 그대로 열린다**.

### 경계 드래그로 크기 조절

레이아웃은 트랙마다 몫을 가진 CSS grid 다 (`grid-template-columns: 1.4fr 0.6fr`).
경계를 끌면 **이웃한 두 트랙만** 몫을 주고받으므로 합이 변하지 않는다 —
한 창이 커진 만큼 반대쪽이 정확히 그만큼 작아지고, 나머지 창은 흔들리지 않는다.

손잡이는 **실제로 창이 갈라지는 구간에만** 놓인다. 예를 들어 왼쪽에 세로로 긴 창이 있고
오른쪽만 위아래로 나뉜 배치라면, 가로 경계 손잡이는 오른쪽 칸에만 생긴다. 그 선을
가로지르는 긴 창은 위아래 몫의 합이 그대로여서 크기가 변하지 않는다.

끄는 동안에는 화면만 먼저 따라가고, 손을 뗄 때 한 번 Rust 로 보내 스냅샷에 기록한다.
아무리 밀어도 트랙이 `MIN_TRACK_WEIGHT` 아래로는 내려가지 않아 창이 사라지지 않는다.

### 병합 차단 규칙

병합 대상 중 **프로그램이 열린 창은 최대 하나**여야 한다.

| 조합 | 결과 |
| --- | --- |
| 터미널 + 빈 블럭 | 병합 · 터미널이 확장되어 나타남 |
| 에디터 + 빈 블럭 | 병합 · 에디터가 확장되어 나타남 |
| 빈 블럭 + 빈 블럭 | 병합 · 빈 블럭 |
| 터미널 + 터미널 | **차단** — 토스트로 사유만 표시 |
| 터미널 + 에디터 | **차단** — 토스트로 사유만 표시 |

살아남는 창은 드래그 순서와 무관하게 *유일하게 점유된 창*이다. 점유 창이 최대 하나이므로
병합이 실행 중인 셸을 죽이는 일은 구조적으로 일어나지 않는다.

드래그 중에는 ① 대상 창 강조 ② 합집합 사각형 오버레이 ③ 커서를 따라다니는 배지
④ 비대상 창 감쇠가 함께 나타나고, 병합 불가일 때는 놓기 전에 붉은 톤으로 바뀐다.

### 모션

터미널 앱이라 **입력을 기다리게 하는 모션은 두지 않는다.** 90~220ms(`--dur-1/2/3`), 감속 곡선, 그리고
무엇이 어디서 어디로 갔는지를 보여 주는 데만 쓴다. 윈도우의 "애니메이션 효과" 를 끄면
(`prefers-reduced-motion`) 모두 사라진다.

- **배치가 바뀔 때** — 분할·병합·교환·닫기·전체화면에서 창이 한 프레임에 순간이동하던 것을, 창 윤곽이
  옛 자리에서 새 자리로 움직여 이어 준다. 분할한 새 칸은 가르는 선에서 펼쳐지고, 병합으로 먹힌 창은 그
  자리에서 흐려진다(`lib/layoutMotion.ts`). 흔한 FLIP 처럼 창 자체를 `scale` 하지 않는다 — 터미널 글자가
  늘어나고, 크기를 매 프레임 바꾸면 xterm 이 다시 맞추며 ConPTY 까지 다시 그린다. 창은 곧바로 새 자리에
  그려지고 그 위로 빈 윤곽만 움직이므로 다음 키는 곧바로 먹는다.
- **전체화면에서도 다른 창을 지우지 않는다.** 고른 창이 격자 전체를 덮고 나머지는 그 뒤에 숨는다
  (`pane--behind`). 예전에는 창 모드로 돌아올 때마다 다른 터미널이 xterm 을 새로 만들고 버퍼를 다시 받았다.
- **분할 미리보기** — 우클릭 메뉴·편집 막대의 분할 항목에 마우스를 올리면 그 창의 어느 쪽이 새 칸이
  되는지 점선으로 보여 준다.
- **오버레이** — 메뉴·팔레트·모달·토스트가 들어올 때 살짝 떠오르고, 닫힐 때 빠진다. 닫히는 순간 리액트가
  노드를 지우므로 퇴장은 그 모습을 복제한 것 위에서 돈다(`useExitMotion`) — 상태는 이미 닫혀 있어
  다음 키·클릭은 곧바로 먹고, 복제본은 `inert` 라 아무것도 받지 않는다.
- **피드백** — 고른 창은 제목줄 아래 강조선, 거부된 병합은 그 창들이 짧게 흔들리고, 앱을 다시 켜며
  AI 를 대신 띄운 창에는 `↻ claude 이어가는 중` 칩이 잠깐 뜬다. 버튼은 누르는 순간이 보이고, 키보드
  포커스는 강조색 링 하나로 통일했다.

## 터미널

```
[Rust]  ConPTY ─ portable-pty ─ alacritty_terminal::Term  (8k 스크롤백 · 검색 · 직렬화)
          └ raw bytes ──Channel──▶ [Webview] xterm.js  (렌더 · 한글 IME)
                        ◀──invoke── 키 입력
```

`rterm-term` 은 **수동 미러**다. `Event::PtyWrite`(DA·커서 위치 응답 등)는 xterm.js 가 이미
돌려주므로 여기서는 절대 PTY 로 되쓰지 않는다 — 그러면 응답이 두 번 가서 입력이 깨진다.

주의할 ConPTY 동작 두 가지:

- 시작하자마자 커서 위치(DSR `ESC[6n`)를 묻고 **답이 올 때까지 아무것도 내보내지 않는다.**
  그래서 셸은 xterm 이 준비된 뒤에 띄운다(`pty_open`).
- 자식이 끝나도 master 파이프를 곧바로 닫지 않는다. 종료 감지는 파이프 EOF 가 아니라
  전용 대기 스레드의 `child.wait()` 로 한다.

세션을 옮겨 다녀도 셸은 죽지 않는다. xterm 이 사라지면 `pty_detach` 로 출력 채널만 떼고,
돌아오면 `pty_open` 이 살아 있는 슬롯에 다시 붙어 Rust 버퍼를 replay 한다.

다시 붙일 때는 글자만이 아니라 **상태**까지 옮긴다(`TermCore::serialize_for_attach`). 화면 속
프로그램이 그대로 살아 있기 때문이다 — 예전처럼 글자만 다시 그리면 `claude`·`codex`·`vim` 이 도는
창을 다녀왔을 때 새 xterm 은 일반 버퍼에 마우스 보고도 꺼진 상태라, 휠이 프로그램으로 가지 않고
xterm 자기 버퍼를 굴렸다. 그래서 대체 화면이면 그 진입(`?1049h`)을 맨 앞에, 커서 자리와 프로그램이
켜 둔 모드(마우스 보고 `?1000/1002/1003/1006`·괄호 붙여넣기·커서 키·포커스 보고·커서 숨김)를 맨
뒤에 싣고, 화면 줄은 뒤쪽 빈 줄까지 그대로 옮겨 ConPTY 의 절대 좌표와 xterm 의 화면이 어긋나지
않게 한다. 앱을 다시 켜서 복원할 때는 이것을 쓰지 않는다 — 그 화면의 프로그램은 이미 끝났다.

### 배색

윈도우 터미널의 기본 배색인 **Campbell** 을 이 앱의 따뜻한 톤으로 옮겼다. 그대로 가져올 수는
없다 — Campbell 은 자기 배경(`#0C0C0C`)에서도 빨강 3.2:1 · 파랑 2.4:1 로 어둡고, 이 앱의
배경(`#1b1a18`)에서는 더 나빠진다.

그래서 **색상(hue)은 Campbell 을, 밝기는 대비로** 정했다. OKLCH 에서 색상마다 sRGB 안에서
낼 수 있는 가장 선명한 색을 고르고, 보통색은 배경 대비 5.2:1, 밝은색은 8:1 에 맞췄다.
값은 `lib/termTheme.ts` 에 있고, **규칙은 테스트가 지킨다**(`termTheme.test.ts`) — 색을 손봐도
읽을 수 없게 되지는 않는다.

예전 배색에서 고친 것이 하나 더 있다. 보통색과 밝은색의 밝기 차가 1.15~1.35배뿐이었고
`white` 와 `foreground` 가 같은 값이었다. xterm 은 굵은 글자를 밝은색으로 그리므로
(`drawBoldTextInBrightColors` 기본값 `true`) **굵게가 화면에서 보이지 않았다.** 지금은 모든
짝이 1.5배 이상 벌어져 있다. 굵은 얼굴(Cascadia Mono 700)도 함께 담아 가짜 굵기를 없앴다.

낱말 단위 선택(더블클릭)의 경계도 윈도우 터미널의 `wordDelimiters` 기본값으로 맞췄다 —
xterm 기본값은 `--flag=value` 나 `C:\a\b` 를 한 낱말로 잡는다.

`BEL` 은 소리 대신 그 창의 테두리를 한 번 밝힌다(xterm 5.5 에는 벨 표시가 아예 없다).
창이 여럿인 앱에서 소리는 어느 창인지 알려 주지 못한다.

`Ctrl+Shift+K`(스크롤백 비우기)는 화면과 **Rust 버퍼에 같은 시퀀스를 먹인다** —
`CUP`·`ED 2`·`ED 3`(`pty_clear`). 두 가지를 지키기 위해서다.

- 화면만 비우면 스냅샷이 여전히 옛 줄을 들고 있어서, 세션을 다녀오거나 앱을 다시 켤 때 방금 버린
  것이 되살아난다 — 재연결이 `serialize_scrollback` 을 다시 써 주기 때문이다.
- 한쪽에만 다른 조작을 하면(xterm 의 `clear()` 는 프롬프트 줄 하나를 남기고 코어는 남기지 않는다)
  두 버퍼가 어긋난 채 갈라진다. 같은 바이트를 주면 같은 상태가 된다.

**대체 화면에서는 거부한다.** `claude`·`codex`·`vim` 이 도는 자리인데, 거기에는 버릴 히스토리가
아예 없고(`ED 3` 는 아무 일도 하지 않는다) `ED 2` 는 그 프로그램이 그려 둔 화면만 지워 버린다 —
프로그램은 지워진 것을 모르므로 다시 그리지도 않는다. 실제로 그런지는 테스트로 확인해 두었다
(`commands/pty.rs` 의 `the_clear_sequence_is_useless_on_the_alternate_screen`).

GPU 컨텍스트를 잃으면(절전 복귀·드라이버 갱신) WebGL 애드온을 떼고 DOM 렌더러로 돌아간다.
그러지 않으면 셸은 계속 도는데 화면만 옛 글자로 얼어붙는다.

### 스크롤

터미널의 스크롤 막대는 **앱이 직접 그린다**(`components/TerminalScrollbar.tsx`, 기하는
`lib/scrollbar.ts`). 브라우저 것을 쓰지 않는 이유가 둘 있다.

- **크기** — 손잡이 길이는 보이는 줄의 비율이라 스크롤백 8,192줄이 다 차면 30줄짜리 창에서
  0.4% 다. 게다가 `::-webkit-scrollbar` 를 한 번이라도 선언하면 크로미움은 최소 길이를 우리에게
  맡기므로, 그냥 두면 손잡이가 **점**이 되어 잡을 수가 없다. 확대하면 보이는 줄이 더 줄어 증상이
  심해진다. 그래서 손잡이를 36px 아래로는 줄이지 않는다. 대가는 정밀도(1px 이 수십 줄)지만 **닿는
  범위는 그대로다** — 맨 위·맨 아래는 언제나 정확히 버퍼의 처음과 끝이고, 한 줄씩은 휠이 맡는다.
- **드래그** — `claude`·`codex` 처럼 출력을 쏟아내는 프로그램 밑에서는 브라우저 손잡이가 커서에서
  빠져나간다. 버퍼가 가득 찬 뒤에도 xterm 이 스크롤을 올려 둔 사용자를 위해 줄이 밀릴 때마다
  보는 자리를 하나씩 당기기 때문이다 — 글자는 제자리인데 손잡이만 위로 기어오른다. 그래서
  **끄는 동안에는 손잡이 자리를 포인터가 쥐고**, 버퍼가 바뀌어도 길이만 따라간다. 놓으면 다시
  버퍼가 말하는 자리로 맞춘다.

빈 곳을 누르면 한 화면씩 넘어가고, 막대 위에서도 휠이 먹는다(막대는 `.xterm` 밖이라 xterm 이
보지 못하므로 대신 굴려 준다). `Ctrl+휠` 은 그대로 확대로 넘긴다. `claude`·`codex` 가 도는 창
(`pane.ai`)에서는 막대를 늘 또렷하게 둔다.

#### 대체 화면 — 가상 뷰포트

`claude`·`codex`·`vim`·`less` 처럼 **대체 화면**을 쓰는 동안은 사정이 다르다. 거기에는 xterm
스크롤백이 없어서 `baseY` 가 0 이다 — "총 몇 줄"도 "지금 몇 번째 줄"도 **없다.** 화면을 넘기는
것은 프로그램 자신이고, 그가 어디를 보고 있는지 알려 주는 프로토콜은 없다.

움직이는 방법은 휠뿐이다. 프로토콜은 우리가 짜지 않는다 — xterm 이 `.xterm` 에 걸어 둔 휠 처리기를
대신 눌러 주면(`lib/termWheel`) 마우스 보고를 켠 프로그램에는 SGR 보고가, 안 켠 프로그램에는 커서
키가 나간다. 막대가 할 수 있는 일이 정확히 "휠을 굴린 것" 뿐이라 어떤 프로그램 밑에서도 새로 생기는
위험이 없다. 그 갈림길이 크기도 정한다: 화살표 경로는 한 이벤트에 크기를 실어 **한 번만** 보내면
xterm 이 화살표 n 개로 펴 주지만(`writePty` 도 한 번), SGR 보고에는 **크기가 실리지 않아** 한
이벤트가 딱 한 칸이라 칸 수만큼 나눠 보내야 한다(프레임당 상한을 두고 나머지는 다음 프레임으로).

자리는 **보낸 휠 칸을 세어 추정한다**(`lib/scrollbar` 의 가상 뷰포트). 값이 둘이다 — `pos`(바닥에서
올라간 칸 수)와 `span`(트랙 전체가 뜻하는 칸 수, 곧 축척). 사상은 `offsetPx = travel × (1 - pos/span)`
하나뿐이고 드래그도 이 식으로 그린다. **이득을 제스처 시작 때 한 번만 재기** 때문에 식이
`offsetPx = 시작자리 - 끈거리` 로 펴져 손잡이가 포인터에 정확히 붙고, 손을 떼도 같은 식으로 그리므로
**자리가 튀지 않는다.** 보낼 칸 수가 끈 거리의 순수 함수라 되돌려 끌면 보낸 것도 그대로 되돌아온다.
본문에서 굴린 진짜 휠도 같은 `pos` 에 접는다 — 안 그러면 화면은 움직였는데 손잡이는 가만히 있어
막대가 거짓말을 한다(우리가 만든 휠은 표시해 두고 걸러 낸다).

**위쪽 끝은 알 수 없다.** 그래서 `span` 은 `pos` 위로 늘 여유를 남긴다 — 겪어 보지 못한 구간에서는
손잡이가 트랙 위쪽 1/4 지점에 머물고 꼭대기에는 닿지 않는다. 그 자리가 곧 "위에 더 있을 수 있다"는
뜻이다. 맨 위를 **감지하려는 시도는 하지 않는다.** 판단 근거가 "휠을 보냈는데 화면이 안 변한다"뿐인데
`claude` 는 답하는 내내 스피너를 다시 그려 하필 거기서 발화하지 않고, 반대로 오발화하면 위에 내용이
남았는데 드래그가 막히는 — 놓으면 바닥으로 튀던 옛 증상보다 더 나쁜 — 고장이 된다. 그리고 맨 위는
손잡이의 **축척에만** 영향을 준다. 축척이 조금 틀린 것은 눈에 안 띄지만 드래그가 막히는 것은 바로
티가 난다.

**바닥은 다르다.** `pos` 를 바닥 기준으로 세므로 바닥이 유일하게 필요한 기준점이고, 손잡이를 트랙
맨 아래까지 끌어내리면 한 화면치를 더 내려 보내 **증명한다** — 프로그램이 알아서 잘라 내므로 넘치게
보내도 무해하고, 이것이 추정치가 아래쪽으로 어긋났을 때 스스로 낫는 길이다. 단 화살표 경로에서는
보내지 않는다: 마우스 보고를 켜지 않은 프로그램에게 그 휠은 `ESC[B`, 곧 ↓ 키라서 `claude` 의
입력창에서는 히스토리 탐색이 되고 `fzf` 에서는 선택이 움직인다.

추정치는 대체 화면을 드나들 때, 그리고 마우스 보고가 켜지거나 꺼질 때 초기화한다 — 후자에서는 한 칸이
뜻하는 줄 수가 3배쯤 달라져 축척의 의미가 바뀐다. 갈림길이 `pane.ai` 가 아니라 `buffer.active.type`
하나인 것도 일부러다. `pane.ai` 는 2분 주기 프로세스 스캔이라 방금 띄운 `claude` 는 최대 2분간
인식되지 않는데, 그 사이 막대 동작이 달라지면 오히려 이상하다.

**복원 직후에도 휠이 바로 먹는다.** xterm 의 휠은 `.xterm-viewport` 의 DOM `scrollTop` 을 움직이고,
그 스크롤 영역의 높이는 `Viewport.syncScrollArea()` 가 맞추는데, 그 동기화는 버퍼가 **스크롤될 때**와
치수가 바뀔 때만 불린다. 복원은 수천 줄을 부팅 직후 — 레이아웃·글꼴이 자리 잡기 전 — 에 한꺼번에
쓰고, 그 뒤 프롬프트는 화면 안에서만 그려져 다시 스크롤이 일어나지 않는다. 그래서 낡은 높이가 남아
휠이 먹지 않다가, PageUp/PageDown 을 눌러 ConPTY 가 화면을 다시 그리면 그제서야 살아났다. 이제는
복원 내용을 다 쓴 뒤(쓰기 콜백), 글꼴이 다 온 뒤, 창이 다시 보일 때 한 줄 올렸다 내리는 왕복으로
일부러 동기화를 일으킨다(`TerminalPane` 의 `resyncViewport`). 왕복이라 위로 올려 읽던 자리는 그대로다.

xterm 의 진짜 스크롤바는 지우지 않고 **투명하게 자리만** 남겨 둔다. 폭을 0 으로 만들면 FitAddon 이
글자 폭에서 빼는 값이 `offsetWidth 차이 || 15` 라 오히려 15px 를 빼서 우리 막대와 어긋난다.
폭을 우리 막대와 같게 두면 마지막 칸이 막대 밑으로 들어가지 않는 것이 저절로 보장된다.

### 셸 통합

윈도우에서는 남의 프로세스 작업 폴더를 밖에서 읽을 수 없다. 그래서 Windows Terminal 과 같은 방법을
쓴다 — **셸이 프롬프트마다 `OSC 9;9;<경로>` 로 스스로 알리게** 하고, `rterm-term` 의 전용 스캐너가
그 바이트를 건진다(`alacritty_terminal` 은 창 제목 말고는 OSC 를 올려 주지 않는다).

| 셸 | 방법 |
| --- | --- |
| `pwsh` · `powershell` | `%APPDATA%\rterm\shell\rterm-init.ps1` 을 `-NoExit -Command ". …"` 로 dot-source. 프로필이 로드된 **뒤** 라서 사용자 `prompt` 를 덮지 않고 감싼다 |
| `cmd` | `PROMPT=$e]9;9;$P$e\$P$G` 환경변수 하나로 끝 |
| `wsl` | `PROMPT_COMMAND` 를 `WSLENV` 에 얹어 넘기고, 복원할 때는 `wsl.exe --cd` |
| `ssh` | 없음 — 원격 셸은 우리 것이 아니다 |

창 제목줄은 셸이 `OSC 0/2` 로 알려 주는 제목을 그대로 싣는다 — 지금 그 창에서 무엇이 도는지가
보인다. 알려 주기 전까지는 셸 이름(`pwsh · 새 터미널`)이 남는다. 값을 정하는 것은 화면 속
프로그램이므로 제어문자와 방향 전환 문자를 걷어내고 길이를 자른 뒤에 싣는다
(`lib/termText.ts`) — 그러지 않으면 제목 하나로 제목줄 배치가 깨지거나 보이는 순서가 뒤집힌다.

`RTERM_NO_SHELL_INTEGRATION` 을 세우면 통째로 꺼진다. oh-my-posh 처럼 `prompt` 를 나중에 다시
정의하는 도구를 쓰면 마커가 사라지는데, 그때는 폴더 복원만 조용히 꺼질 뿐 아무것도 깨지지 않는다.

### 탐색기로 열기

터미널을 우클릭하면 메뉴 **맨 아래**에 `↗ 탐색기로 열기` 가 있다. 그 터미널이 지금 서 있는
폴더(`pwd`)를 윈도우 탐색기로 연다. 어느 폴더인지는 Rust 가 아는 순서대로 정하고(`pane_reveal_cwd`),
물러난 자리에서 열었으면 토스트가 그렇다고 적어 준다.

| 순서 | 폴더 | 토스트 |
| --- | --- | --- |
| 1 | 셸이 **지금** 알려 주고 있는 폴더(`live_cwd`) | `탐색기 · <경로>` |
| 2 | 창에 마지막으로 적힌 폴더 — 셸 통합이 없거나 셸이 끝났을 때 | `… 마지막으로 알던 폴더를 엽니다 · <경로>` |
| 3 | 세션 설정의 폴더 | `… 세션 폴더를 엽니다 · <경로>` |

스냅샷의 창별 폴더가 아니라 셸의 실시간 값을 먼저 보는 이유는 스냅샷이 명령이 오갈 때만 갱신돼
그 사이의 `cd` 를 놓치기 때문이다. 나눈 자리의 터미널이 폴더를 물려받을 때도 같은 판정을 쓴다.

**폴더 문자열은 화면 속 프로그램이 정할 수 있다.** 창별 폴더는 셸이 `OSC 9;9` 로 스스로 알린
값인데, 그 바이트를 찍을 수 있는 것은 셸만이 아니다(`cat evil.bin` 한 번이면 아무 경로나 실린다).
그래서 하이퍼링크를 열 때와 같은 자세로 막는다(`commands/reveal.rs`).

- **폴더만** 넘긴다. `explorer.exe <파일>` 은 그 파일을 기본 처리기로 **여는** 것이라 `.exe`·`.lnk`
  하나면 그대로 실행이다. `/select,…`·`shell:startup` 같은 것도 폴더가 아니라 여기서 함께 걸린다.
- **네트워크 경로(UNC)는 열지 않는다.** `\\evil.tld\share` 는 윈도우가 그 호스트에 붙으며 NTLM 을
  흘린다. 존재를 확인하는 것만으로도 붙으러 가므로 파일 시스템을 만지기 **전에** 거른다.
- 제어문자·방향 전환 문자가 섞였거나, 상대 경로거나(윈도우에서는 WSL 의 `/home/…` 이 여기서
  걸린다), 그 폴더가 없으면 다음 후보로 물러난다. 셸은 거치지 않는다 — `explorer.exe` 에 평범한
  argv 하나로 넘긴다.

## 스냅샷

`%APPDATA%\rterm\sessions\snapshot.json` (tmp → rename 원자적 쓰기).
세션 · 레이아웃 · 터미널 스크롤백 8,192 라인 · 창별 확대 배율 · 마크다운 뷰 모드,
그리고 **창별 작업 폴더와 그 창에서 돌고 있던 AI** 를 기록한다.
레이아웃이 바뀔 때마다 즉시 저장하고, 나머지는 창을 닫을 때와 2분마다 갱신한다.

### 끄기 전 상태로 돌아오기

다시 켜면 각 터미널이 **끄기 전 폴더** 에서 뜬다. 셸 통합이 알려 준 폴더를 창마다 기억해 두었다가
`pty_open` 이 그 자리에서 셸을 띄우기 때문이다. 그 폴더가 없어졌으면 세션 기본 폴더로 물러서고,
물러섰다는 사실을 복원 배너에 적는다.

`claude` 나 `codex` 가 돌고 있었다면 그것도 다시 띄운다. 무엇이 돌고 있었는지는 스냅샷을 저장하는
순간 **셸의 자손 프로세스를 한 번 훑어** 알아낸다 — 사용자가 직접 쳤든 ↑ 로 불러왔든 탭 완성으로
채웠든 같은 답이 나온다. 폴더가 먼저 복원되므로 이어붙이기는 세션 ID 없이
`claude --continue` / `codex resume --last` 로 충분하다.

훑을 때는 실행 파일 경로를 따로 청하고(`with_exe`), 이름을 비교할 때는 경로와 확장자를 뗀다.
윈도우의 프로세스 이름은 `claude.exe` 처럼 **확장자까지** 붙어 오는데, 예전에는 그것을 `claude` 와
곧바로 비교해서 **네이티브로 설치한 claude**(`~\.local\bin\claude.exe`)가 한 번도 잡히지 않았다 —
npm 설치(`node … claude-code\cli.js`)만 복원되고 나머지는 셸 프롬프트만 남던 이유다.

다시 띄우는 명령은 **첫 프롬프트가 뜬 뒤에** 친다(셸 통합 마커를 최대 5초 기다린다, 마커가 없는
셸은 400ms). 프로필이 무거운 pwsh 는 예전의 고정 400ms 보다 늦게 떠서, 그 사이에 친 글자가
프롬프트 앞에 섞이는 일이 있었다.

한계: WSL·SSH 창의 AI 는 복원하지 않는다(프로세스가 가상머신·원격 안에 있어 보이지 않는다).
`--continue` 는 **그 폴더의 가장 최근 대화**를 고르므로, 같은 폴더에서 claude 를 둘 띄운 분할 창은
둘 다 같은(가장 최근) 대화로 열린다.
WSL 의 폴더 복원은 `wsl.exe --cd` 로 동작하고, SSH 는 폴더도 복원하지 않는다.

### 마크다운 뷰어

표시 범위는 참고 저장소 [`swpark3179/markdown-viewer`](https://github.com/swpark3179/markdown-viewer)
가 `marked` 로 얻던 만큼을 직접 다룬다 — 라이브러리를 들이지 않은 이유는 **본문의 HTML 을
언제나 이스케이프하기 위해서**다. 마크다운 파일은 남이 준 것일 수 있고, 이 앱의 웹뷰에는
터미널과 파일 시스템이 붙어 있다.

**문서 표시**

- 제목 1~6 단계 · 문단 잇기(원문의 줄바꿈이 화면의 줄바꿈이 되지 않는다) · 줄 끝 공백 두 칸의
  진짜 줄바꿈 · 밑줄 제목(setext).
- 글머리/번호 목록과 **들여쓰기만큼의 중첩**, 체크박스, 시작 번호(`3.` 부터).
- 표의 `:---:` **열 정렬**, 좁은 창에서는 표만 따로 가로로 넘어간다.
- 여러 줄 인용(인용 안의 목록·코드까지), 가로줄, 취소선, 꺾쇠 자동 링크.
- 문서 맨 앞의 `---` **front matter** 는 본문이 아니라 메타데이터로 접어서 보여 준다.
- `snake_case_name` 이 기울임으로 둔갑하지 않고, 코드 스팬 안의 별표는 글자로 남는다.
- **코드 블록** — 언어 배지와 복사 버튼이 달린 카드로 나온다. 문법 강조는
  `highlight.js` 를 **코드 블록이 실제로 있을 때만** 동적으로 불러와 입힌다
  (등록 언어: rust · js/ts · json · bash · powershell · python · go · java · c/c++ · c# ·
  css · html · yaml · toml · sql · diff · markdown).
- **mermaid** — ` ```mermaid ` 블록은 다이어그램으로 그려진다. 이것도 필요할 때만 로드하며,
  뷰어 테마에 맞춘 색을 쓴다. 문법이 틀리면 오류 문구와 함께 **원본을 그대로**
  보여 준다 — 내용을 잃는 것보다 낫다.

**읽기 도구** (뷰어 위쪽 줄)

| 도구 | 하는 일 |
| --- | --- |
| `☰ 목차` | 제목을 훑어 목차를 만든다. 누르면 그 자리로 가고, 스크롤하면 지금 읽는 제목이 켜진다. |
| `⌕ 찾기` · `Ctrl+F` | 문서 안에서 찾기. 대소문자를 가리지 않고, `Enter`/`Shift+Enter` 로 다음·이전, `n / m` 으로 몇 번째인지 보여 준다. |
| 글꼴 | 산세리프 · 세리프 · 고정폭. |
| `⇤⇥` | 본문 폭을 읽기 좋은 폭(46em)으로 좁히거나 창 가득 채우거나. |
| `☾ / ☀` | 밝은 · 어두운 뷰어 테마. 다이어그램과 문법 강조 색도 함께 바뀐다. |

- 창 맨 아래 **얇은 막대**가 얼마나 읽었는지 알려 주고, 위쪽 줄 오른편에 `줄 · 단어 · 글자` 수가
  나온다.
- **읽던 자리를 기억한다** — 세션을 다녀오거나 뷰어/에디터를 오가도 맨 위로 튕기지 않는다.
- 목차는 그려진 제목(`data-md-heading`)에서 읽는다. 원문을 다시 파싱하지 않으므로 목차가
  가리키는 자리와 화면에 있는 자리가 어긋날 수 없다.

**본문 링크** — 종류마다 가는 곳이 다르다.

| 링크 | 눌렀을 때 |
| --- | --- |
| `https://` · `mailto:` | OS 기본 브라우저 (웹뷰가 문서 자리에서 이동해 버리면 뷰어가 통째로 사라진다) |
| `#제목` | 같은 문서 안의 그 제목으로 스크롤 (앵커 이름은 깃허브와 같은 규칙) |
| `./guide.md` · `docs/api.md` | 문서 위치 기준으로 풀어 **빈 블럭에 그 파일을 연다** |
| `javascript:` · `data:` · `file:` | 링크로 만들지 않는다 |

웹 주소와 `data:image/` 그림은 그대로 그리고, 웹뷰가 읽을 수 없는 `./shot.png` 같은 경로는
자리와 경로만 남긴다 — 깨진 그림보다 무엇이 있어야 하는지 알려 주는 편이 낫다.

뷰어 표시 설정(테마·글꼴·목차·폭)은 **창이 아니라 읽는 사람의 것**이라 앱 전체에 한 벌로
브라우저 저장소(`rterm-md-view-v1`)에 남는다. 레이아웃·셸 버퍼와 같은 무게로 스냅샷에 넣지
않는다.

### 이미지 뷰어

- 배율 단계 10 % ~ 1600 %, `⤢ 맞춤` 은 창 크기에 맞춘다 (원본이 작으면 확대하지 않는다).
- `Ctrl+휠` 로 확대, 끌어서 이동. 배율은 창별로 스냅샷에 남는다.
- **스포이드** — 켜면 커서를 따라 색이 실시간으로 읽히고, 클릭하면 `0x00ff00` 꼴로
  클립보드에 복사된다. rgb 값과 원본 픽셀 좌표도 함께 보여 준다.
- 이미지 자체는 스냅샷에 담지 않는다. 경로만 남기고 창을 열 때마다 다시 읽는다
  (base64 를 스냅샷에 넣으면 파일이 수십 MB 로 부푼다). 상한은 32 MB.

## 새 파일 만들기

빈 블럭은 여는 자리이자 **만드는 자리**다. `✚ 새 파일` (빈 블럭 · 우클릭 메뉴 · 파일 열기
창 아래 · 명령 팔레트) 로 마크다운(`.md`)이나 평문(`.txt`)을 그 자리에 바로 만든다.

- 이름에 확장자를 적지 않으면 고른 종류가 붙는다. `docs/설계 노트` 처럼 **하위 폴더**도 적을
  수 있고, 없는 폴더는 만들어 준다.
- 만들어지는 곳은 언제나 **세션 작업 폴더 아래**다. 절대 경로도 `..` 도 받지 않는다.
  윈도우가 싫어하는 이름(`< > : " | ? *`, 끝의 점·공백, `NUL`·`COM1` 같은 예약 이름)은
  누르기 전에 창이 먼저 알려 준다.
- 이미 있는 파일은 덮어쓰지 않는다. 만들기는 `create_new` 로 열어 쓰므로, 확인과 쓰기 사이에
  생긴 파일을 날리는 일도 없다.
- 마크다운은 **파일 이름을 `#` 제목으로** 넣고 에디터로, 평문은 빈 파일로 열린다.
  갓 만든 문서는 읽을 것이 없으니 곧바로 쓸 수 있는 쪽이 맞다.

만들기와 열기는 Rust 명령 하나(`pane_create_file`)다. 둘로 나누면 파일만 생기고 창은 비어 있는
중간 상태가 생긴다.

## 파일 편집

`.md` 는 뷰어/에디터 토글, 그 외 텍스트 파일은 서식 툴바가 붙은 편집기로 열린다.

- **라인 잘라내기** — 선택 없이 `Ctrl+X` 를 누르면 캐럿이 있는 줄이 통째로 잘려 나간다.
- **되돌리기** — `Ctrl+Z` / `Ctrl+Y`. 편집 기록은 앱이 직접 들고 간다. contenteditable 의 기본
  undo 는 우리가 DOM 을 직접 건드리는 조작(라인 잘라내기·표 넣기)과 어긋나기 때문이다.
  연속으로 친 글자는 한 덩어리로 묶여 한 번에 되돌아간다.
- **저장** — `Ctrl+S`(터미널에 포커스가 있을 때는 `Ctrl+Shift+S`). `.md` 는 원문 그대로,
  리치 텍스트는 평문으로 되돌려 쓴다.

### 저장하지 않은 변경

편집 후 저장하지 않은 창을 닫거나 앱을 끝내려 하면 **저장 · 저장하지 않고 진행 · 취소**
세 갈래를 묻는다. 앱 종료는 프론트엔드가 기본 닫기를 되돌린 뒤 물어보므로,
취소하면 창도 터미널도 그대로 남는다. (그래서 Rust 쪽 정리는 창 이벤트가 아니라
실제 종료 시점인 `RunEvent::Exit` 에서 한다 — 취소했는데 셸이 죽는 일이 없도록.)

터미널에 포커스가 있을 때는 위 표의 `Ctrl+Shift+*` · `Ctrl+,` · 확대 조합과 클립보드 조합만
앱이 가져가고 나머지는 전부 셸로 간다(`Ctrl+B`/`Ctrl+E` 같은 readline 편집이 살아 있다).

`Ctrl+Shift+<글자>` 를 고른 이유가 있다. xterm 은 그 조합에서 **어떤 바이트도 내보내지 않으므로**
(`common/input/Keyboard.ts` 의 ctrl 분기는 `!shiftKey` 를 요구한다) 셸에서 빼앗을 것이 없다.
같은 이유로 저장은 `Ctrl+S` 에서 `Ctrl+Shift+S` 로 옮겼다 — `Ctrl+S` 는 셸이 관찰하는 진짜 키
(`0x13` · XOFF · readline 의 정방향 검색)라서 앱이 가져가면 터미널에서 그 키가 죽는다.
터미널 밖(에디터 패널)에서는 이 관문을 지나지 않으므로 `Ctrl+S` 가 그대로 듣는다.

### 클립보드

윈도우 터미널과 같은 규칙이다.

- **`Ctrl+C`** — 선택한 영역이 있으면 복사하고 선택을 지운다. 없으면 예전 그대로 `^C` 가 셸로 가
  실행 중인 명령을 끊는다. 복사 뒤 선택이 지워지므로 한 번 더 누르면 언제나 인터럽트다.
  **한글 입력 상태에서도** 그렇다 — 크로미움은 그때 `Ctrl+C` 에 IME 표시(`keyCode` 229)를 붙여 주기도
  하는데, xterm 은 그런 키를 IME 의 것으로 보고 `^C` 를 보내지 않고 버린다(`CompositionHelper.keydown`).
  조합 중이 아니면 우리가 같은 바이트를 대신 보낸다(`lib/keys.ts` 의 `imeStrayControl`). `Esc` 도 같다.
- **`Ctrl+V`** — 붙여넣기. **어디서나** 그렇다(윈도우 터미널과 같다). 한때는 `vim` 의 비주얼
  블록을 살리려고 대체 화면에서만 그 프로그램에 넘겼는데, 요즘 `claude` 가 바로 그 대체 화면에
  UI 를 그려서 정작 붙여넣기가 가장 필요한 자리에서만 안 되는 꼴이 됐다. 가려지는 두 자리에는
  `Ctrl+Q` 를 쓴다 — vim 의 비주얼 블록(`:h CTRL-Q` 가 바로 이 상황을 위해 안내하는 키)과
  readline 의 quoted-insert 둘 다.
- `Ctrl+Shift+C/V`, `Ctrl+Insert`/`Shift+Insert`, 가운데 클릭, 우클릭 메뉴도 모두 같은 일을 한다.
- 붙여넣기는 **괄호 붙여넣기(bracketed paste)** 로 감싸여 들어가므로 여러 줄을 붙여도 한 줄씩
  실행되지 않는다. 클립보드 안에 끝 표식(`ESC[201~`)이 들어 있으면 미리 지운다 —
  그러지 않으면 그 뒤가 명령으로 실행된다.
- `ssh`·`tmux`·`vim` 안에서 복사한 것도 **OSC 52** 로 윈도우 클립보드까지 온다.
  반대 방향(원격이 내 클립보드를 읽는 것)은 막아 두었다.
- 마우스를 쓰는 프로그램(`htop` 등)이 켜져 있을 때 드래그 선택은 `Shift` 를 함께 누른다.
- 스크롤을 올려 옛 내용을 읽던 중에 붙여넣으면(가운데 클릭 포함) 화면이 바닥으로 돌아온다 —
  방금 넣은 게 스크롤에 가려 안 보이는 일이 없게. 반대로 복사는 지금 보던 자리를 지킨다.
- **`claude`·`codex` 안에서도 그대로 된다** — 드래그 선택 → `Ctrl+C` 는 어떤 프로그램이 셸에서
  돌든 상관없이 화면에 찍힌 글자만 본다. 붙여넣기도 마찬가지다: 요즘 `claude` 는 UI 를 대체 화면에
  그리지만 위에서 적었듯 `Ctrl+V` 는 거기서도 붙여넣기다. 마우스 모드를 켜지 않는 화면에서는
  평소처럼 드래그하면 되고, 어떤 서브 화면이 마우스를 가져가더라도 위 `htop` 예외와 같이
  `Shift+드래그` 로 우회된다.

### 줄바꿈

VT 에는 `Shift+Enter` 를 나타낼 바이트가 **없다.** `Shift` 를 누르고 있어도 `Enter` 는 CR 한
글자라서, 셸도 그 안의 프로그램도 평범한 `Enter`(제출)와 구분할 수 없다. 윈도우에서 이 문제를
푸는 길이 마이크로소프트가 만든 **win32-input-mode** 다(`microsoft/terminal#4999`, `#530`).

ConPTY 는 부팅하자마자 `ESC[c ESC[?1004h ESC[?9001h` 를 우리에게 보낸다(`src/host/VtIo.cpp` 의
`StartIfNeeded`). 마지막 것이 "키를 `INPUT_RECORD` 모양 그대로 달라" 는 청이다. 알아들으면
(`lib/win32Input.ts`) 그때부터 줄바꿈을 이렇게 보낸다 — **`Ctrl+J` 의 눌림과 뗌**이다.

```
ESC [ 74 ; 36 ; 10 ; 1 ; 8 _      ESC [ 74 ; 36 ; 10 ; 0 ; 8 _
      │    │    │   │   └ dwControlKeyState = LEFT_CTRL_PRESSED   (뗌: bKeyDown = 0)
      │    │    │   └ bKeyDown = 1
      │    │    └ UnicodeChar = 10 (LF)
      │    └ wVirtualScanCode = 0x24  (J 자리)
      └ wVirtualKeyCode = VK_J
```

### 왜 `Shift+Enter` 가 아니라 `Ctrl+J` 인가

이 자리에서 고를 수 있는 키가 여럿인데, **클라이언트가 콘솔 레코드를 읽는지 VT 바이트를 읽는지에
따라 결과가 갈린다.** 클라이언트가 `ENABLE_VIRTUAL_TERMINAL_INPUT` 을 켜 두면(`wsl.exe`·`ssh.exe`,
Node 의 `RAW_VT` 모드 등) conhost 가 레코드를 **다시 VT 로 번역해서** 준다
(`inputBuffer.cpp`: `if (vtInputMode) { _termInput.HandleKey(...) }`). 그 번역은 `UnicodeChar` 를
보지 않고 가상 키만 본다(`terminalInput.cpp` 의 `case VK_RETURN`).

| 보내는 키 | 레코드를 읽는 쪽 (`codex` → crossterm) | VT 로 번역되는 쪽 |
| --- | --- | --- |
| `Shift+Enter` | `(Enter, SHIFT)` → 줄바꿈 ✓ | `\r` → **제출** ✗ |
| `Ctrl+Enter` · `Ctrl+Shift+Enter` | `(Enter, CTRL[, SHIFT])` → 아무것도 아님 ✗ | `\n` ✓ |
| `Ctrl+M` | `(Char('m'), CTRL)` → 줄바꿈 ✓ | `\r` → **제출** ✗ |
| **`Ctrl+J`** | `(Char('j'), CTRL)` → 줄바꿈 ✓ | `\n` ✓ |

`Ctrl+J` 만 양쪽에서 줄바꿈이다.

- **레코드를 읽는 쪽** (`codex` → crossterm): `VK_J` + `LEFT_CTRL_PRESSED` →
  `KeyEvent{ Char('j'), CONTROL }`. crossterm 은 특수 키가 아닌 가상 키에 대해
  `ToUnicodeEx(vk, sc, 수정자 없음)` 으로 "그 키의 맨 글자" 를 되찾으므로 `'j'` 가 나온다
  (`event/sys/windows/parse.rs` 의 `get_char_for_key`). 그것이 codex 줄바꿈 목록의 첫 항목인
  `ctrl(Char('j'))` 다(`keymap.rs` 의 `editor.insert_newline`). 제출은 `plain(Enter)` 하나뿐이라
  (`chat_composer.rs` 의 `submit_keys`) 스칠 일이 없다.
  윈도우에서는 crossterm 의 `supports_keyboard_enhancement()` 가 늘 `Ok(false)` 라
  (`terminal/sys/windows.rs`: "This always returns `Ok(false)` on Windows") kitty 키보드
  프로토콜 길이 아예 막혀 있고, 이 길만 남는다.
- **VT 로 번역되는 쪽** (`wsl.exe`·`ssh.exe` 등): `VK_J` 는 문자 키이고 Ctrl 이 눌려 있으므로
  그 제어문자 `0x0a` 가 나간다 — 예전과 **똑같은** 순수 LF 다. WSL·SSH 안의 리눅스 `codex` 는
  그 LF 를 다시 `Ctrl+J`(역시 줄바꿈 자리)로 읽는다.
- **레코드를 바이트로 펴는 쪽** (`claude` → Node/libuv 의 `RAW` 모드): `UnicodeChar` 가 0 이
  아니면 그 글자를 그대로 내보낸다(`uv_tty_read`). 여기에 LF 를 실어 두었으니 역시 LF 다.

뗌까지 보내는 것도 이유가 있다. conhost 는 앞뒤로 붙은 같은 눌림 레코드를 하나로 합치면서
`wRepeatCount` 만 올리는데(`inputBuffer.cpp` 의 `_CoalesceEvent`), crossterm 은 `wRepeatCount` 를
보지 않아 레코드 하나당 이벤트 하나만 만든다. 사이에 뗌이 끼지 않으면 빠르게 두 번 누른 줄바꿈이
한 번으로 삼켜진다. 뗌 자체는 어디에서도 글자를 만들지 않는다 — VT 번역은 뗌에서 곧바로 돌아가고
(`terminalInput.cpp` 의 `if (!key.keyDown)`), codex 는 `KeyEventKind::Release` 를 거르고,
libuv 는 뗌을 아예 무시한다.

모드를 청하지 않은 상대에게는 win32 시퀀스를 들이밀지 않고 예전처럼 LF 한 바이트만 보낸다.
Claude Code 공식 `/terminal-setup` 이 쓰는 `ESC+CR`(메타+엔터) 관례는 쓰지 않는다 — `codex` 는
그 조합을 그냥 제출로 읽는다.

> **왜 LF 만으로는 부족했나.** 보내려는 키가 결국 `Ctrl+J` 인데도 이 모드가 필요한 까닭은,
> ConPTY 의 바이트→레코드 되짚기가 손실이 있기 때문이다. C0 제어문자는 `VkKeyScanW` 로 되짚어
> 키를 찾는데(`InputStateMachineEngine::_GenerateKeyFromChar`), `'\n'` 에 대응하는 키가 자판에
> 없다. 그래서 클라이언트에게는 `Ctrl+J` 가 아니라 **가상 키와 수정자가 어긋난 이벤트**가
> 도착하고, 그 뒤는 프로그램마다 다른 예비 경로에 맡겨진다. 같은 키를 이 모드로 보내면 되짚기를
> 건너뛰고 값이 그대로 전해진다.

줄바꿈은 붙여넣기처럼 스크롤을 바닥으로 돌려놓는다 — 스크롤을 올려 둔 채 줄을 넣으면 xterm 이
원래 하는 자동 스크롤을 우리가 가로채는 키 처리기가 건너뛰기 때문에, 우리가 대신 해 준다.

### Esc 와 몇몇 Alt 조합도 레코드로 보낸다

ConPTY 의 입력 파서는 읽은 덩어리가 **ESC 로 끝나면** 그것이 `Esc` 키인지, 잘려서 도착한 시퀀스의
앞머리인지 알 수 없다. 그래서 짐작으로 고른다(`stateMachine.cpp` 의 `ProcessString` 끝): win32
시퀀스를 **한 번도 받은 적이 없으면** `Esc` 로, **한 번이라도 받았으면** 잘린 시퀀스로 보고 다음
바이트가 올 때까지 붙잡아 둔다(`_encounteredWin32InputModeSequence`). 이 모드를 쓰는 터미널은 모든
키를 레코드로 보내니 맨 ESC 가 올 리 없다는 가정이다.

줄바꿈만 레코드로 보내면 그 가정이 틀린다. 그 창에서 `Shift+Enter` 를 **한 번 누른 뒤로는**:

- `Esc` 가 나가지 않는다. 다시 눌러도 앞의 것을 버리고 또 붙잡는다 — `claude` 의 `/usage` 처럼
  `Esc` 로만 닫히는 화면이 닫히지 않던 자리다.
- 그다음에 누른 키에 Alt 가 붙는다. `Ctrl+C` 라면 `Ctrl+Alt+C` 가 되어
  (`ActionExecuteFromEscape` → `_DoControlCharacter(ETX, writeAlt=true)`) ConPTY 의 Ctrl+C 처리를
  비켜 간다 — `npm run` 이 첫 `Ctrl+C` 에 멈추지 않던 자리다.

그래서 **파서를 열어 둔 채 끝나는 입력만** 골라 같은 키의 레코드(눌림·뗌)로 바꾼다(`inputSequence`).
통째로 일치할 때만 바꾸므로 붙여넣기·터미널 응답은 걸리지 않고, 방향키(`ESC[A`)·Alt+글자(`ESC b`)
처럼 닫힌 채 끝나는 입력은 한 바이트도 바뀌지 않는다.

| xterm 이 내보낸 것 | 키 | 레코드 (`Vk;Sc;Uc;…;Cs`) |
| --- | --- | --- |
| `ESC` | `Esc` (`Ctrl+[` · `Ctrl+3` 도 같은 바이트) | `27;1;27;…;0` |
| `ESC ESC` | `Alt+Esc` | `27;1;27;…;ALT` |
| `ESC [` · `ESC ]` | `Alt+[` · `Alt+]` | `VK_OEM_4` · `VK_OEM_6` + ALT |
| `ESC O` · `ESC P` · `ESC X` | `Alt+Shift+O/P/X` | 그 글자 키 + ALT·SHIFT |
| `ESC ^` · `ESC _` | `Alt+Shift+6` · `Alt+Shift+-` | 그 글자 키 + ALT·SHIFT |

Alt 조합까지 넣는 것은 `Esc` 만 바꾸면 ConPTY 의 짐작이 "첫 `Shift+Enter`" 가 아니라 "첫 `Esc`" 에서
뒤집혀, bash 의 `M-_` 같은 키가 지금보다 일찍 막히기 때문이다. 받는 쪽에서 보면 바뀌는 것이 없다 —
바이트를 읽는 쪽(`wsl`·`ssh`·`claude`)에게는 conhost 가 레코드를 예전과 같은 `ESC`·`ESC [` 로 펴서
주고, 레코드를 읽는 쪽(`codex`·PSReadLine)은 진짜 `Esc`·`Alt+[` 를 받는다. 뗌은 줄바꿈과 같은 이유로
함께 보내고, 어디에서도 글자를 만들지 않는다. `^C` 는 바꾸지 않는다 — 맨 `0x03` 이 ConPTY 의 Ctrl+C
전용 길을 탄다.

### 한글을 치던 중에 눌러도 순서가 지켜진다

조합 중인 음절은 xterm 이 `compositionend` 자리에서 곧바로 보내지 않고 **한 틱 뒤에** 보낸다
(`CompositionHelper._finalizeComposition` 의 `setTimeout(…, 0)`). 브라우저가 조합이 끝난 **뒤에**
밀어 넣는 `input` 이벤트까지 봐야 진짜로 확정된 글자를 알 수 있기 때문이다.

그 틈에 줄바꿈을 그 자리에서 써 버리면 아직 나가지 않은 음절을 앞질러서, **마지막 글자가 다음 줄
머리로 밀린다** — `claude`·`codex` 에서 보이던 자리다. 그래서 조합의 시작과 끝을 따라가다가
(`compositionstart`·`compositionend`) 그 사이에 눌린 줄바꿈은 붙잡아 두고, 글자가 나간 **뒤에**
보낸다. 우리 `compositionend` 처리기는 xterm 것보다 나중에 붙으므로 거기서 잡는
`setTimeout(…, 0)` 도 xterm 이 먼저 잡아 둔 것 뒤에 놓인다 — 음절이 먼저, 줄바꿈이 뒤.

키 이벤트의 `isComposing` 만 보는 것으로는 모자라다. 크로미움은 IME 가 음절을 확정하며 넘긴
`Enter` 를 `compositionend` **뒤에** 주기도 하는데(그때 `isComposing` 은 이미 거짓이다), 그 순간에도
글자는 여전히 위의 `setTimeout` 안에 남아 있다. 그래서 "조합이 끝나기를 기다리는 중" 까지를
줄바꿈을 미룰 자리로 본다. 한글 입력 상태에서 대신 보내는 `Ctrl+C`·`Esc`(위 클립보드 절)도 같은
틈이면 그 글자 뒤로 간다. 조합 **중**에 누른 것은 IME 에 맡긴다 — 언제 끝날지 모르는데 붙잡아 두면
한참 뒤에 `^C` 가 튀어나간다.

### 하이퍼링크

`OSC 8` 하이퍼링크와 평범한 글자 속 `http(s)` 주소를 **`Ctrl+클릭`** 으로 연다(윈도우 터미널과
같은 규칙). **주 버튼**으로만 연다 — 우클릭(창 메뉴)·가운데 클릭(붙여넣기)에도 같은 처리기가
불리기 때문이다. 마우스를 올리면 **실제 주소**가 칩으로 뜬다.

조심할 것이 둘 있다.

- xterm 은 `linkHandler` 를 주지 않으면 자기 기본 동작(`OscLinkProvider.ts` 의
  `defaultActivate`)으로 물러나는데, 그것은 ① 번역되지 않은 영어 `confirm()` 을 띄우고
  ② 수정자를 요구하지 않아 지나가는 클릭에도 열리며 ③ `window.open()` 으로 연다. Tauri
  웹뷰(WebView2)에서 그것이 무엇을 여는지는 앱이 정하지 않고, 무엇보다 우리 주소 검사를
  지나지 않는다. 그래서 처리기를 반드시 우리가 준다.
- 주소를 정하는 것은 화면 속 프로그램이고, `OSC 8` 은 **보이는 글자와 실제 주소를 따로 싣는다.**
  `ESC]8;;https://evil.tld ESC\ https://github.com ESC]8;; ESC\` 는 github 주소로 보이면서
  evil.tld 로 간다. 스킴 검사로는 못 잡으므로 `Ctrl` 을 요구하고 실제 주소를 눈에 보여 준다.

넘기기 전에 화면 쪽에서 `new URL()` 로 ASCII 로 정규화한다 — xterm 은 한글 경로·IDN 호스트가 든
주소도 링크로 내주는데(`OscLinkProvider.ts` 의 걸러내기도 `new URL()` 하나뿐이다) Rust 검사는
ASCII 만 받아서, 그러지 않으면 눌러도 오류만 뜬다.

실제 열기는 Rust(`commands/link.rs`)가 `http`·`https` 만 통과시킨 뒤 `explorer.exe <url>` 로 한다.
다른 스킴은 윈도우의 임의 처리기로 이어진다(`ms-msdt:` · `search-ms:` · `shell:` · `file:`,
UNC 경로는 NTLM 을 흘린다). 셸을 거치지 않는 것도 의도다 — `cmd /C start` 는 인자 규칙이 달라
표준 라이브러리의 이스케이프가 통하지 않는다.

## 디자인과 다른 점

의도적으로 바꾼 것들:

- **AI 세션 이어붙이기** — 디자인은 터미널 입력에서 `claude --resume` 을 가로채 ID 를 붙이는
  방식이었다. 입력 가로채기는 readline 편집을 망가뜨리므로 걷어냈다. 저장해 두는 세션 ID 도
  없다 — 앱을 다시 켤 때 `claude --continue` / `codex resume --last` 가 **그 창의 현재 폴더**
  에서 가장 최근 대화를 알아서 찾고, 창의 폴더는 앱이 기억했다 복원하기 때문이다(아래 "끄기 전
  상태로 돌아오기" 참고). 한동안 세션 헤더에 살아 있는 창에서 아무 때나 수동으로 이어붙일 수
  있는 `claude`/`codex` 칩도 있었지만, 잘 안 쓰인다고 판단해 뺐다 — 필요하면 그 창에서
  `claude --continue` 를 직접 치면 된다.
- **파일 드롭** — Tauri 웹뷰는 HTML5 파일 드롭을 막으므로 네이티브 드래그 이벤트로 실제
  경로를 받는다.
- **파일 저장** — 디자인에 없던 `Ctrl+S` 를 추가했다. `.md` 는 원문 그대로, 리치 텍스트는
  평문으로 되돌려 쓴다(소스 파일에 서식 마크업을 남기지 않기 위함).
- **시드 데이터** — 디자인의 데모 3세션 대신 홈 디렉터리 기준 세션 하나로 시작한다.
  그 세션은 빈 블럭이 아니라 터미널 하나가 세션을 가득 채운 모습으로 열린다.
- **내장 명령** — 디자인의 `help`/`ls`/`cat` 흉내는 없다. 실제 셸이 처리한다.
- **이미지 뷰어** — 디자인에 없던 창 종류다. 병합 규칙에서는 터미널·에디터와 똑같이
  "열린 프로그램" 으로 센다.
